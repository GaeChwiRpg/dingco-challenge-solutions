### 근거형 질문

## 선택과 근거

- Todo.user가 FK를 관리하고 User.todos는 `mappedBy` 읽기 방향으로 둔다.
- 편의 메서드는 양쪽 컬렉션과 참조를 동시에 변경한다.
- cascade remove와 orphanRemoval은 부모 삭제/컬렉션 제거라는 서로 다른 시나리오로 테스트한다.

## 기준 구현·기록 예시

```java
public void addTodo(Todo todo) {
  todos.add(todo);
  todo.assignTo(this);
}

@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "user_id")
private User user;
```

## 근거형 질문 답변

1. DB의 외래 키 변경 명령을 한쪽 매핑에서만 만들기 위해 주인이 필요하다. 두 쪽이 각각 FK를 갱신하면 충돌하거나 불필요한 SQL이 생긴다.
2. LAZY는 사용 시점만 늦춘다. 목록 N개를 순회하며 각 연관을 접근하면 결국 N개의 추가 SELECT가 발생한다.
3. cascade REMOVE는 부모 제거가 자식 제거로 전파되는 경우이고 orphanRemoval은 부모 컬렉션에서 관계가 끊긴 자식을 삭제하는 경우다.
4. DB 반영은 주인이 담당하지만 같은 트랜잭션의 객체 그래프는 자동으로 양쪽이 맞지 않는다. 편의 메서드는 메모리 상태의 일관성을 지킨다.
