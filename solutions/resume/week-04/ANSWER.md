# 동시성 버그 해결 ADR — 기준 답안

> 이 문서는 복사할 “모범 문장”이 아니라 통과 가능한 **검증 밀도**를 보여주는 기준 PR입니다. 본인 프로젝트의 코드·로그·수치가 다르면 결론도 달라져야 합니다.

## 한 문장 결론

동시 시작 장벽으로 재고 불변식 위반을 반복 재현하고, 원자적 조건 UPDATE와 락 전략을 같은 경합에서 비교한다.

## 기준 미션

## Week 4. 트랜잭션과 동시성

쿠폰 또는 재고 시나리오에서 경합을 재현하고 락 전략을 선택합니다.

### 이번 PR

**동시성 버그 재현·해결 ADR과 근거형 답변**

1. 재고 또는 쿠폰 시나리오에서 동시에 요청하면 불변식이 깨지는 테스트를 작성합니다.
2. 낙관적 락, 비관적 락, 원자적 쿼리 중 최소 두 전략을 같은 경합 조건에서 비교합니다.
3. 정합성, 처리량, 재시도와 복잡도를 근거로 최종 선택을 ADR에 기록합니다.

### 필수 제출 증거

- 반복 가능한 동시성 테스트
- 전략별 비교 수치
- 최종 ADR와 이력서 bullet
- 근거형 질문 13~16 답변

### 근거형 질문

1. MVCC가 있어도 애플리케이션의 동시성 제어가 필요한 이유는 무엇인가요?
2. 낙관적 락의 재시도는 어디까지 허용하고 어떻게 폭주를 막나요?
3. 비관적 락을 선택하면 데드락과 처리량을 어떻게 관측해야 하나요?
4. 현재 전략이 적합하지 않게 되는 경합 수준이나 요구사항은 무엇인가요?

## 선택과 근거

- 성공 수 + 남은 재고 = 초기 재고 불변식을 assertion한다.
- 원자적 `UPDATE ... WHERE stock > 0`을 기본안으로 선택한다.
- 재시도 폭주가 필요한 낙관적 락과 긴 잠금의 비관적 락은 현재 단일 감소 요구에서 기각한다.

- [x] 실패하는 동시성 테스트
- [x] 전략별 성공/실패·처리시간
- [x] 불변식 검증
- [x] 선택/기각/재검토 ADR

## 기준 구현·기록 예시

```sql
UPDATE coupon
SET stock = stock - 1
WHERE id = :id AND stock > 0;
```

검증 불변식: `successfulClaims + remainingStock == initialStock`, `remainingStock >= 0`.

## 근거형 질문 답변

1. MVCC는 DB 격리를 제공하지만 read–modify–write라는 애플리케이션 불변식의 lost update를 자동으로 해결하지 않는다.
2. 낙관적 재시도는 횟수·전체 시간·jitter를 제한하고 큐 길이/충돌률로 폭주를 감시한다.
3. lock wait, deadlock count, transaction duration과 throughput을 함께 관측한다.
4. 감소 외 복잡한 검증이 한 원자 쿼리로 표현되지 않거나 경합이 극단적으로 커지면 직렬화 큐나 다른 전략을 재검토한다.

## 다른 답도 통과할 수 있는 조건

- 다른 프레임워크·도구·전략을 골라도 요구한 실패 경계와 결과 정합성을 같은 수준으로 재현하면 통과할 수 있습니다.
- 결론이 반대여도 입력 조건, 비교 기준, 실행 로그와 재검토 조건이 연결되면 유효합니다.
- 이 기준 PR의 예시 수치나 문장을 본인 성과처럼 옮기면 증거로 인정하지 않습니다.
