# 안전한 위임 기준선 — 기준 답안

> 이 문서는 복사할 “모범 문장”이 아니라 통과 가능한 **검증 밀도**를 보여주는 기준 PR입니다. 본인 프로젝트의 코드·로그·수치가 다르면 결론도 달라져야 합니다.

## 한 문장 결론

반복 작업의 입력·출력·금지 행동·중단 조건을 먼저 고정하고 동일 인수 테스트로 사람-only와 AI 보조 흐름을 비교한다.

## 기준 미션

## Week 1. AI 협업 기준선과 위임

도구보다 먼저 반복 업무 기준선과 사람이 책임질 검증 경계를 정의합니다.

### 이번 PR

**반복 작업 하나를 안전하게 위임하고 기준선 측정하기**

1. 본인 프로젝트 또는 제공 실습 저장소 중 하나를 선택하고 반복 작업 한 개를 고정합니다.
2. 입력, 기대 출력, 금지 행동, 사람이 확인할 경계와 중단 조건을 위임 명세로 작성합니다.
3. 동일한 인수 테스트로 기존 방식과 AI 방식의 시간, 재작업 횟수와 결함 수를 비교합니다.

### 필수 제출 증거

- 위임 명세
- 초안과 최종 diff
- 동일 기준의 시간·품질 비교
- 재사용 체크리스트

### 근거형 질문

1. AI에게 맡긴 범위와 사람이 끝까지 책임지는 범위를 왜 그렇게 나눴나요?
2. 속도 외에 결과 품질을 비교하기 위해 어떤 동일 기준을 사용했나요?
3. 이번 위임을 즉시 중단해야 하는 실패 신호는 무엇인가요?

## 선택과 근거

- 문서 frontmatter 검증 한 작업만 위임한다.
- 파일 삭제·외부 publish·의존성 추가는 금지한다.
- 테스트 실패나 범위 밖 diff가 생기면 즉시 사람에게 반환한다.

## 제출 증거의 최소 완성선

- [x] 위임 명세
- [x] 사람-only/AI 동일 테스트
- [x] 초안–최종 diff
- [x] 시간·재작업·결함 기록

## 기준 구현·기록 예시

```yaml
task: validate-frontmatter
input: content/posts/**/*.md
allowed: frontmatter normalization only
forbidden: body rewrite, delete, publish, dependency change
acceptance: npm test -- frontmatter
stop: scope drift OR test bypass OR destructive action
```

## 근거형 질문 답변

1. 반복 탐색과 기계적 수정은 AI에 맡기고 요구 해석, 범위 변경과 최종 검증은 사람이 책임진다.
2. 같은 fixture와 acceptance test, 범위 밖 파일 수, 리뷰 결함 수를 품질 기준으로 쓴다.
3. 금지 경로 수정, 테스트 우회, 검증 명령 불실행 또는 입력에 없는 외부 쓰기가 중단 신호다.

## 다른 답도 통과할 수 있는 조건

- 다른 프레임워크·도구·전략을 골라도 요구한 실패 경계와 결과 정합성을 같은 수준으로 재현하면 통과할 수 있습니다.
- 결론이 반대여도 입력 조건, 비교 기준, 실행 로그와 재검토 조건이 연결되면 유효합니다.
- 이 기준 PR의 예시 수치나 문장을 본인 성과처럼 옮기면 증거로 인정하지 않습니다.
