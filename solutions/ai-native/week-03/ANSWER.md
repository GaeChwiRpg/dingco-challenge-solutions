# 이슈에서 검증 PR까지 — 기준 답안

> 이 문서는 복사할 “모범 문장”이 아니라 통과 가능한 **검증 밀도**를 보여주는 기준 PR입니다. 본인 프로젝트의 코드·로그·수치가 다르면 결론도 달라져야 합니다.

## 한 문장 결론

외부 도구는 최소 권한으로 연결하고 이슈의 인수 조건–브랜치–테스트–리뷰–PR을 추적 가능한 신뢰 사슬로 만든다.

## 기준 미션

## Week 3. MCP·Git·에이전트 검증 루프

외부 도구와 병렬 에이전트를 연결하되 PR과 테스트를 신뢰 경계로 유지합니다.

### 이번 PR

**이슈에서 검증된 PR까지 안전하게 자동화하기**

1. 인수 조건과 비범위를 가진 작은 이슈를 작성하고 AI가 변경 브랜치와 PR까지 만들게 합니다.
2. 테스트, 정적 검사와 리뷰 결과를 병합 전 필수 신뢰 경계로 둡니다.
3. 외부 도구별 읽기·쓰기 권한, 중단 조건과 실패 후 복구 순서를 체크리스트로 남깁니다.

### 필수 제출 증거

- 연결된 이슈와 PR
- 테스트·리뷰 로그
- 도구별 권한표
- 실패 복구 체크리스트

### 근거형 질문

1. 외부 도구 연결에서 최소 권한을 적용한 구체적인 지점은 어디인가요?
2. 병렬 에이전트의 결과가 충돌하거나 서로를 덮어쓰지 않도록 어떤 경계를 만들었나요?
3. 테스트 통과만으로 자동 병합하면 안 되는 변경은 무엇인가요?

## 선택과 근거

- 이슈에는 인수 조건 3개와 비범위 2개를 둔다.
- 에이전트별 파일 소유권을 나누고 공유 파일은 한 에이전트만 수정한다.
- 테스트 통과 뒤에도 권한·마이그레이션·사용자 노출 변경은 사람 리뷰를 요구한다.

## 제출 증거의 최소 완성선

- [x] 이슈/PR 연결
- [x] 검사 로그
- [x] 도구 권한표
- [x] 실패 시 branch 보존·revert 순서

## 기준 구현·기록 예시

```markdown
Tool | Read | Write | Forbidden | Stop
Issue | selected issue | comment | delete/edit others | scope changes
GitHub | repo/branch | branch + PR | main, secrets, org settings | protected path diff
CI | logs | none | rerun-until-green concealment | nondeterministic failure
```

## 근거형 질문 답변

1. 이슈는 read, GitHub는 해당 repo branch/PR write만 허용하고 org 설정·secret·main direct push 권한은 주지 않는다.
2. 각 에이전트의 파일 소유권과 출력 계약을 고정하고 통합자는 결과를 cherry-pick/merge 전에 다시 검증한다.
3. 권한, 데이터 마이그레이션, 결제, 개인정보와 비가역 외부 작업은 테스트가 통과해도 자동 병합하지 않는다.

## 다른 답도 통과할 수 있는 조건

- 다른 프레임워크·도구·전략을 골라도 요구한 실패 경계와 결과 정합성을 같은 수준으로 재현하면 통과할 수 있습니다.
- 결론이 반대여도 입력 조건, 비교 기준, 실행 로그와 재검토 조건이 연결되면 유효합니다.
- 이 기준 PR의 예시 수치나 문장을 본인 성과처럼 옮기면 증거로 인정하지 않습니다.
