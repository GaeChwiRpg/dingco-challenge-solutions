# internal-review-contrast 기준 풀이

이 PR은 정답 코드만 비교하는 자료가 아닙니다. 제출을 끝낸 뒤 아래 순서로 비교하세요.

1. 본인 풀이의 상태 정의와 불변식을 한 문장으로 설명합니다.
2. 공식 풀이의 경계 조건이 본인 코드에서 빠졌는지 확인합니다.
3. 시간·공간 복잡도를 입력 상한에 대입합니다.
4. 다른 언어 풀이에서 구현 차이와 동일한 알고리즘 구조를 찾습니다.

## 문제 안내

# 리뷰 순서의 대비 최대화

한 주 동안 수집한 `n`개의 풀이 리뷰가 있습니다. 리뷰 `i`를 읽으면 `scores[i]`만큼의 새로운 통찰을 얻습니다. 그러나 같은 오개념을 반복해서 다루는 두 리뷰는 함께 선택할 수 없습니다. 함께 선택할 수 없는 리뷰 쌍이 `conflicts`로 주어집니다.

정확히 `k`개의 리뷰를 선택해 얻을 수 있는 통찰 점수의 최댓값을 반환하세요. 가능한 선택이 없다면 `-1`을 반환합니다.

## 함수 계약

```text
max_review_insight(scores, conflicts, k) -> integer
```

- `1 <= n <= 18`
- `1 <= k <= n`
- `1 <= scores[i] <= 100`
- `conflicts`의 각 원소는 서로 다른 인덱스 `[a, b]`이며 중복 쌍은 없습니다.

## 예시

```text
scores = [8, 6, 7, 5, 9]
conflicts = [[0, 1], [1, 2], [3, 4]]
k = 3
answer = 24  # 0, 2, 4번 리뷰
```

```text
scores = [5, 4, 3]
conflicts = [[0, 1], [0, 2], [1, 2]]
k = 2
answer = -1
```

## 제출 전 사고 질문

1. 점수가 큰 순서대로 고르는 그리디가 실패하는 반례를 만드세요.
2. 인덱스 `i`에서 선택/건너뛰기 두 분기는 어떤 상태를 공유하나요?
3. 남은 리뷰 수로 k개를 채울 수 없을 때 탐색을 중단하는 조건을 적으세요.
4. 충돌 검사를 매번 전체 쌍에서 찾는 방법과 인접 집합을 미리 만드는 방법을 비교하세요.

선택 집합, 현재 점수, 다음 인덱스를 상태로 정의하고 완전성·충돌 안전성·가지치기 조건을 설명하세요. 최악 시간 복잡도도 적어주세요.
