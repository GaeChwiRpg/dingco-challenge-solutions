# programmers-12987 기준 풀이

이 PR은 정답 코드만 비교하는 자료가 아닙니다. 제출을 끝낸 뒤 아래 순서로 비교하세요.

1. 본인 풀이의 상태 정의와 불변식을 한 문장으로 설명합니다.
2. 공식 풀이의 경계 조건이 본인 코드에서 빠졌는지 확인합니다.
3. 시간·공간 복잡도를 입력 상한에 대입합니다.
4. 다른 언어 풀이에서 구현 차이와 동일한 알고리즘 구조를 찾습니다.

## 문제 안내

# 숫자 게임

문제 원문은 [프로그래머스 12987](https://school.programmers.co.kr/learn/courses/30/lessons/12987)에서 확인하세요.

## 필요한 사전 개념

정렬은 앞으로의 선택을 비교 가능한 순서로 만듭니다. 가장 작은 A를 이길 수 있는 가장 작은 B를 쓰는 선택이 왜 미래의 선택지를 가장 많이 남기는지 증명해보세요.

## 제출 전 사고 질문

1. 현재 B가 가장 작은 남은 A를 이기지 못한다면 다른 A를 이길 수 있나요?
2. A를 이길 수 있는 더 큰 B 대신 가장 작은 가능한 B를 써도 손해가 없는 이유는 무엇인가요?
3. 위 두 문장을 교환 논리로 연결해 그리디 선택을 증명하세요.
4. 정렬 없이 매 라운드 상대를 찾는 풀이의 최악 시간 복잡도는 얼마인가요?

## 필수 반례

- 모든 B가 패배
- 모든 B가 승리
- 같은 숫자가 여러 번 등장
- `b == a`는 승리가 아닌 경우

## 제출물

두 포인터가 가리키는 값과 이미 처리한 구간의 의미를 불변식으로 적고, 그리디 선택의 안전성과 복잡도를 설명하세요.
