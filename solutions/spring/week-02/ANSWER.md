# 컨테이너와 프록시 해부 — 기준 답안

> 이 문서는 복사할 “모범 문장”이 아니라 통과 가능한 **검증 밀도**를 보여주는 기준 PR입니다. 본인 프로젝트의 코드·로그·수치가 다르면 결론도 달라져야 합니다.

## 한 문장 결론

주입 대상 선택, 객체 생명주기와 프록시 여부를 추측하지 않고 런타임 클래스와 호출 로그로 확인한다.

## 기준 미션

## Week 2. 프록시·빈·DI로 보는 스프링 컨테이너

스프링의 자동화를 프록시, 빈 생명주기와 의존성 주입 코드로 검증합니다.

### 이번 PR

**스프링 컨테이너 자동화 해부와 근거형 답변**

1. 동일한 인터페이스의 두 구현체를 만들고 명시적인 빈 선택 기준을 적용합니다.
2. 생성자 주입으로 연결한 객체와 직접 new한 객체의 차이를 검증 테스트로 보여줍니다.
3. 빈 생성과 의존성 호출 순서를 로그로 남기고, 프록시가 적용되는 지점이 있다면 실제 클래스 정보를 확인합니다.

### 필수 제출 증거

- 빈·DI 검증 코드
- 생성·호출 순서 로그
- 직접 생성 대비 문서
- 근거형 질문 6~10 답변

### 근거형 질문

1. 스프링이 주입할 구현체를 결정할 수 없을 때 어떤 일이 발생하며 어떻게 해결했나요?
2. 생성자 주입이 필드 주입보다 테스트와 불변성에 유리한 이유는 무엇인가요?
3. 컨테이너가 관리하는 객체와 직접 생성한 객체의 가장 중요한 차이는 무엇인가요?
4. 프록시 객체인지 원본 객체인지 코드로 어떻게 확인할 수 있나요?
5. 이번 실험의 호출 순서 로그가 없었다면 어떤 설명을 검증할 수 없었나요?

## 선택과 근거

- 동일 인터페이스 구현체에는 의미가 드러나는 `@Qualifier`를 두고 생성자 주입한다.
- 직접 `new`한 객체와 빈을 같은 테스트에서 비교해 의존성·후처리기 적용 차이를 드러낸다.
- AOP 적용 전후 클래스명과 호출 순서를 캡처하되 클래스명 자체를 비즈니스 로직에 의존시키지 않는다.

## 제출 증거의 최소 완성선

- [x] 두 구현체 선택 테스트
- [x] 생성자 호출과 `@PostConstruct` 순서
- [x] `AopUtils.isAopProxy` 결과
- [x] 직접 생성 객체와 빈의 의존성 차이

## 기준 구현·기록 예시

```java
@Bean @Qualifier("fast")
TodoPolicy fastPolicy() { return new FastTodoPolicy(); }

TodoService(@Qualifier("fast") TodoPolicy policy) {
  this.policy = policy;
}

assertThat(AopUtils.isAopProxy(todoService)).isTrue();
assertThat(new TodoService(new FastTodoPolicy()).getClass()).isEqualTo(TodoService.class);
```

## 근거형 질문 답변

1. 후보가 둘인데 `@Primary`나 qualifier가 없으면 `NoUniqueBeanDefinitionException`이 발생한다. 이름에 기대기보다 의도가 드러나는 qualifier로 해결한다.
2. 생성자 주입은 필수 의존성을 생성 시점에 완성하고 필드를 final로 유지할 수 있어 단위 테스트에서 대역을 명시적으로 전달할 수 있다.
3. 관리 객체에는 의존성 주입, 생명주기 콜백과 BeanPostProcessor/AOP가 적용된다. 직접 생성 객체에는 이 컨테이너 경계가 없다.
4. `AopUtils.isAopProxy(bean)`과 `bean.getClass()`를 함께 기록한다. 구현 세부인 프록시 클래스명만 단정하지 않는다.
5. 로그가 없다면 생성 후 주입인지, 후처리 뒤 호출인지, advice가 실제 메서드 전후에 실행됐는지를 검증할 수 없다.

## 다른 답도 통과할 수 있는 조건

- 다른 프레임워크·도구·전략을 골라도 요구한 실패 경계와 결과 정합성을 같은 수준으로 재현하면 통과할 수 있습니다.
- 결론이 반대여도 입력 조건, 비교 기준, 실행 로그와 재검토 조건이 연결되면 유효합니다.
- 이 기준 PR의 예시 수치나 문장을 본인 성과처럼 옮기면 증거로 인정하지 않습니다.
